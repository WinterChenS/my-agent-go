🦀 阶段 B · Rust + Tauri
建设目标

技术栈
  • Rust 1.95.0（rust-toolchain 锁定）
  • Tauri v2 桌面宿主
  • React / TS / Vite / Tailwind
  • rusqlite bundled（FTS5 trigram）
范围口径
✓ ADR 0007：换栈决定并实施 ✓ ADR 0008：验收平台确认不变
现状

DECISIONS 决策先行，代码后动
为什么允许自己换壳
8 份 ADR 把「换桌面壳、换承载方式、删平台、迁移凭证、放宽门禁」全部写成必须先留痕的动作：ADR 0004 记宿主依赖、0005 记验收收窄、0006 记范围重定、0007 记换栈、0008 记平台不变。任何一次都不静默执行。
换栈付出的代价
旧实现全量重写，Wails 时代的证据只能作历史参考；换来的是可复现的构建链（--locked、target 锁在 D 盘）与 285 项 Rust 测试——从「能跑起来」升级为「跑错了会红」。
决策复盘
这一年的技术选择不是「越新越好」，而是每收窄一次范围、每换一次壳，都必须同时接受一次门禁的重新审判。
04 门禁 · Pi · 桌面 · 数据 · 验收

技术亮点

01 / 门禁
让「通过」无法伪造
门禁按 case × target × display 三维判定，同一必需位出现两份证据、证据 gateId 串阶段、worktreeDirty 一律判死；退出码 0 / 1 / 2 保真（ADR 0001），禁止 || true、禁止空 suite 判成功、禁止写 passed.json 冒充执行。
02 / Pi
能力协商，而不是假设
宿主 Pi 走认证版本 + 注册 hash + 契约探测三段式，探测用隔离 agentDir、不碰真实 provider 与用户配置；多 Pi 不静默切换，PATH 上的 WeChat node shim 被显式拦截；1.4.0 这类低于最低版本的一律停在 upgrade_available，不进兼容探测。
03 / 桌面
原生 WebView2 与主窗口同窗
浏览器不做外挂窗口，而是同一主窗口右栏的原生子视图：缩放、分栏、焦点、最小化、剪贴板、IME 输入、50 轮连续交互逐项做过真机回归，全部以 Tauri 之前的实物证据链固定行为。
04 / 数据
配置与凭证按「可追溯」设计
CAS + 五层合并保证配置来源可解释、可回溯；SQLite 走 rusqlite bundled 并开 FTS5 trigram，中文检索不依赖外部分词；凭证入 DPAPI，不落明文。
05 / 验收
真实桌面验收，不用静态 UI 冒充
界面与交互由 agent-desktop 驱动真实窗口取证（G0 界面、G1 多 Agent 发现与同步、G2 会话顺序），Pi 真实用例用本机已安装的 Pi 与现有登录；外部观察型用例必须有真实机器与 review 字段，mock 与静态界面不能顶替证据。
05 可复现 · 常绿 · 归属 · 真机

工程质量与门禁

01
构建可复现
全部构建 --locked，工具链由 rust-toolchain.toml 钉在 Rust 1.95.0；CARGO_TARGET_DIR 与 RUSTUP/CARGO_HOME 全部锁在 D 盘，不允许往 C 盘装工具链、不允许构建产物漂移。
02
三道关常绿
每次交付前跑满 cargo fmt / clippy -D warnings / cargo test --workspace，本次体验包记录为 285 passed；前端 vitest 249 passed 且 npm run build 归零，一手数据写进 VERSION.txt 而不是口头承诺。
fmt · 0 clippy · 0 cargo test · 285 vitest · 249
03
证据有归属
183 份证据文件绑定 revision + target + display，dirty 工作区的产物直接拒收；集成测试不再改写已提交的历史证据，verify 会检测运行期脏化。旧 PASS 不自动覆盖新范围。
04
真实窗口检查项
在解压后的真实产物上验收：thinking 与工具卡片按 ledger 顺序（think → call → think）、首 token 前只显示 dots、新建会话清空 transcript，模型按 runtime tab 分组、@skill 芯片可用。
📌 未闭环项（如实记录）
本次体验包基于 57ee76f 之上的工作树，含 54 个未提交改动，因此证据归属需在干净 revision 上重跑；Tauri bundle 按设计禁用，前端从磁盘加载。
质量口径
状态只有 PASS / FAIL / BLOCKED / NOT_RUN，PASS 由证据确定，不由「看起来能用」确定；缺机器就写 BLOCKED，不删目标、不改口径、不伪造证据。
06 窗口 · 单点 · 平台 · 归属

不足与风险

01
交付窗口太窄
全年产出压进 11-03 → 11-15 的 13 天，477 次提交密度过高，评审、复盘与文档沉淀被挤到交付之后；一旦出现误判，返工窗口也只剩几天。
02
单点总线风险
477 次提交、36 个特性分支来自单一作者，bus factor = 1；上下文大量存在于个人脑中，交接靠 handoff 文档兜底，不是可持续的工程结构。
03
跨平台证据缺口
六目标里只有 win-x64 / Windows 10 22H2 有真机证据；mac-x64、mac-arm64、linux-x64、linux-arm64 按 ADR 0005 / 0008 记 deferred——不得据此宣称跨平台。
04
证据归属待收口
体验包建在含 54 个未提交改动的工作树上，G0–G2 未在干净 revision 上重跑；门禁自己的规则是「dirty 判死」，这条也得对自己生效。
诚实口径
未过 G4 不称 Anvil V1 可交付，未过 G5 不称正式发行完成。
本年度结论是「基座成立、验收未闭合」，不是「已完成」。
07 结清证据 → 跨平台真机 → G4/G5 交付

2027 年度规划

整体方向：从 「单机可用的体验包」 推进到 「过 G4 的内部版本、过 G5 的公开发行」
PHASE 1 · 结清
把证据钉回干净 revision
核心工作：拆分 54 个未提交改动 + 重跑 G0–G2
重点目标
  • 未提交改动按模块拆成可审查提交
  • 干净工作树上重跑 G0 界面 / G1 多 Agent / G2 会话
  • v1-gates 的 case 状态逐条对齐当前 revision
  • 历史 PASS 与新范围做显式映射，不默认继承
目标指标
  • 183 份证据全部绑定干净 revision
  • 门禁报告 0 条 dirty / 0 条重复位
  • G0–G2 全部 case 有 PASS 或明确的 BLOCKED 记录
◌ 当前状态：进行中 👤 个人角色：主要负责人
PHASE 2 · 跨平台
补齐四目标真机矩阵
核心方向：mac-x64 / mac-arm64 / linux-x64 / linux-arm64，Linux 双 display 各一份
重点建设
  • 真机环境与架构证据（ENV02）
  • X11 / Wayland 两个会话的 native 套件
  • WebView 承载在各平台的等价行为对照
  • deferred 清单逐条转正或写清阻塞原因
目标
  • 四个目标从 deferred 变为实测 PASS
  • 跨平台声明以真机证据为前提，不再用「应该可以」表述
◌ 当前状态：未开始
PHASE 3 · 交付
G4 / G5 与安装器
核心方向：F06 安装器 + 签名 + 发布通道 + package suite 重跑
重点探索
  • 应用托管安装 / 升级流程（不覆盖外部 Pi）
  • 代码签名与发行通道
  • 重编后的最终包必须重跑 package suite
  • 把 bus factor 从 1 降到 2：双人 review + 文档化交接
目标
  • 内部版本达到 G4
  • 公开版本达到 G5
  • 核心模块双人可维护
◌ 当前状态：规划中
规划总结
2027 年的第一件事不是加功能，而是把 2026 年已经做过的事，用干净证据重新证明一遍。
