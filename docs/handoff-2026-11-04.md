## 偏移与修正优先级

1. **G0 仍未闭合，工作台已经做到 C03。** C01 原依赖 G0，当前执行顺序已经提前。保留现有实现，把它视为可复验成果。先补 G0 和浏览器原型，再推进依赖这些门禁的完整集成。
2. **门禁聚合可丢失平台维度。** `internal/devtools/gate.go` 的 `EvaluateGate` 用 `found[caseID]` 收集证据，同一 case 在不同目标上会相互覆盖，已知 target 的单份结果也可能满足 case。应按 case/subcase × target × display 判定，并验证重复报告、前置 gate 和当前修订。补回归用例：ALL 缺一目标、Linux 缺 Wayland、同 case 两平台一失败、重复/旧修订证据均不可通过。`GetSourceRevision` 目前只取短 HEAD，dirty 工作区的结果也可能被贴上该提交标签。正式证据使用干净源码，或绑定可复验的工作树身份。参见 [门禁实现](../internal/devtools/gate.go) 和 [修订标识](../internal/devtools/evidence.go)。
3. **本地技能同步与 RES02 未对齐。** C03 记录了上一会话的用户意图，保留本机用户级技能发现。当前实现移除了 `-ns`，同名自动发现副本可能继续加载，旧矩阵仍要求不能绕过禁用。把用户级发现和托管技能分开描述，用 ADR/基线/任务/用例同步确定同名冲突与禁用的语义。用真实 Pi 和临时 HOME 分别测试用户级、项目 `.pi/skills`、工作区/祖先 `.agents/skills`、同名副本。`config_isolation.go` 的注释与通道表对项目技能是否被 `-na` 阻断表述不一致，以实测为准。用户级同步不自动授权不可信项目资源。参见 [隔离参数](../internal/runtime/pi/config_isolation.go) 和 [RES02](acceptance/v1-gates.md#安装与资源)。
4. **运行记录把托管列表称作实际加载列表。** `desktop.go` 将 `skills.IDs` 传给 `RunService`，快照直接复制这些 ID。开启自动发现后，此字段未覆盖 Pi 自动发现的用户技能，空列表可能仍有技能。改为准确区分托管启用清单与 Pi 实际可见技能，后者没有可信来源时显示未知。参见 [运行快照](../internal/run/service.go)。
5. **历史证据正在被回写。** 当前 diff 在 `docs/evidence/raw/f04-policy-integration.json` 删除了历史参数 `-ns`，C03 计划也已勾选“提交”。保留旧原始记录，以新运行证据记录新参数和版本，核对 C03 提交与 RES02 实际状态后更新勾选。勿把这次测试或旧截图转成当前门禁 PASS。

F06 延后是已有 ADR 记录的用户决定。任务索引的 G4 依赖已加 F06，但 F06 自身的依赖仍只到 G0，应在下一次维护时补上 G3 前置或等价的执行约束。

## Windows 复验命令

在仓库根使用 PowerShell。Go 测试用临时目录，真实 Pi 的测试定位到仓库隔离安装。前端缺依赖时先按 lockfile 执行 `npm.cmd --prefix frontend ci`。

```powershell
$env:Path = 'D:\Program Files\nodejs;' + $env:Path
go test ./... -count=1
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend test
```

在独立终端开启真实技能集成，完成后关闭该终端或清除变量。

```powershell
$env:Path = 'D:\Program Files\nodejs;' + $env:Path
$env:MYAGENT_PI_WORKER_INTEGRATION = '1'
go test ./internal/resources -run 'TestEnabledSkillAppearsInRealPiPrompt|TestDisabledManagedSkillAbsentInNextRun' -count=1 -v
```

在源码身份和证据目录准备好后生成目标报告，再执行 gate。每次记录实际退出码，避免 `go run` 折叠退出码。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/devtools.ps1 verify --suite=integration --target=win-x64
$reviewRevision = git rev-parse --short HEAD
powershell -ExecutionPolicy Bypass -File scripts/devtools.ps1 gate --id=G0 --evidence="docs/evidence/runs/$reviewRevision/win-x64"
```

上述 G0 命令用于 Windows 单目标诊断。整体验收需在聚合缺陷修复后使用六目标证据树。真机启动使用隔离 `MYAGENT_HOME`、workspace 和本地 fixture，环境搭建参考 [F05 桌面证据](evidence/f05-windows-desktop.md)。
