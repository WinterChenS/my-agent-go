# Anvil V1 产品、UI 与生命周期设计

版本：1.0；日期：2026-11-05；状态：用户已确认的设计规格。

## 1. 目的与权威关系

本规格根据 `docs/ui/Agent-客户端产品原型/`、当前已完成实现和 2026-11-05 的用户确认，定义 Anvil V1 的产品界面、缺失功能、Pi 生命周期和应用自动更新能力。

文档修改完成后，权威顺序调整为：

1. 用户后续明确指令；
2. 本规格；
3. `2026-11-03-v1-execution-baseline.md` 的未被本规格替换部分；
4. 分模块计划、验收矩阵和机器索引；
5. 历史方案与调研。

原型是视觉与交互输入，不是功能完成证据。原型中的静态数字、成功提示、连接状态和示例数据不得直接进入生产实现。若原型行为与安全、权限、数据权威或本规格冲突，以本规格为准。

## 2. 当前实现基础与变更原则

当前仓库已有可复用的真实能力：

- F00–F05、F07 的工具链、Pi 1.5.0 协议基线、RPC worker、权限、运行状态和配置存储；
- C01–C05 的工作台、模型、Skills、MCP 和长期记忆；
- B00/B01 的浏览器契约、fixture 和 Windows WebView2 原生子视图；
- 六目标构建和部分目标运行证据。

这些任务的历史状态和证据保持不变。新的 UI、兼容层和功能使用新 Task ID，不能把已完成任务改回未开始状态，也不能用旧任务的证据证明新界面或新能力已经完成。

实施遵守以下原则：

- 复用已验证服务，不重写 Pi agent loop、provider 协议或外部 MCP client；
- UI 只显示真实后端数据或明确的空、失败、未连接、阻塞状态；
- 每项功能具备真实数据源、失败路径、权限约束、重启持久化和外部判据；
- 缺机器、签名、OAuth 客户端或测试账户时记录 BLOCKED，不用 mock 冒充真实集成；
- 保留六个 OS/CPU 目标和 Linux X11/Wayland 双会话要求。

## 4. 品牌与兼容迁移

正式产品名从 MyAgent 改为 Anvil：

- Windows 可执行文件和安装项为 `Anvil.exe` / Anvil；
- macOS 应用为 `Anvil.app`；
- Linux 桌面项和命令为 `anvil`；
- 内部页面使用 `anvil://`；
- 用户级环境变量改为 `ANVIL_*`；
- 新应用数据目录使用平台标准的 `Anvil` 目录；
- UI、诊断、日志标题、安装包元数据和新证据统一使用 Anvil。

仓库目录与 Go module 暂不改名。`MYAGENT_*` 环境变量保留一个开发兼容周期；同时存在时 `ANVIL_*` 优先，并记录弃用警告和配置来源。非敏感配置和数据库允许从旧开发目录迁移；旧凭证不被自动复制，继续通过已有 credential reference 使用，或要求用户重新录入。

## 5. 信息架构和页面契约

### 5.1 全局壳层

左侧栏包含三个主入口：工作台、对话、Agent。工具与自动化聚合入口展开资源库、记忆、Skill、MCP、连接器、定时任务和设置。侧栏下半部显示按项目分组的会话与普通会话；底部显示当前 Pi 状态和本地用户工作区。

全局搜索支持页面、会话、Agent、Skill、产物和可执行导航动作。所有搜索结果来自真实索引，未建立索引时显示明确不可用状态。

### 5.2 工作台

工作台显示当前运行、待审批、最近会话、最近产物、计划任务摘要和运行健康。统计必须能追溯到本地数据库或运行事件；没有数据时显示空态，不保留原型演示数字。

### 5.3 对话

对话页包含：

- 项目归属、Agent/Profile、模型、思考级别和权限摘要；
- 流式消息、工具调用、审批卡、停止、恢复、失败和上下文限制状态；
- 内容澄清与工具权限分离；
- 文件、目录和 Skill 附件；
- 项目会话和普通会话历史、搜索、分页、置顶、重命名、归档和删除；
- 本地 HTML/Markdown/JSON 导出；
- 右栏浏览器、产物、引用和执行四个分区；
- 产物回到来源轮次；
- 窄窗口下的右栏抽屉。

“思考”只展示 Pi 实际提供的状态或摘要，不展示隐藏推理。审批和运行状态只能由后端事件推进，前端不得在按钮点击后自行标记成功。

### 5.4 Agent

V1 的 Agent 是单个 Profile 的产品化编辑器，支持名称、说明、模型、system prompt、思考级别、Skills、工具、权限边界和记忆设置。V1 不显示子 Agent、自动委派或第三方运行时入口。

权限不能超过系统和工作区上限。原型中的“完全控制”不作为默认值；任何外部写入、删除、付费、提权或对外发送动作仍由统一 policy 判定。

### 5.5 Skill 与 MCP

Skill 支持本地创建、导入、编辑、启停、依赖检查和隔离试运行。链接内容视为不可信输入；安装前只解析清单，不执行仓库说明或脚本。Skill 市场不进入 V1。

MCP 支持 stdio 和 Streamable HTTP，显示真实工具清单、连接状态、错误、重连和权限。未支持的 SSE、WebSocket 或 OAuth 状态不得显示为已连接。

### 5.6 连接器

V1 连接器及最小动作集：

| 连接器 | 读取动作 | 写入或外发动作 |
|---|---|---|
| 邮箱 | 搜索、读取、附件 | 起草、发送 |
| 钉钉 | 读取允许范围 | 发送群消息 |
| 飞书 | 读取文档 | 更新文档、发送消息 |
| Slack | 读取频道 | 回复线程 |
| Notion | 查询页面和数据库 | 创建或更新页面 |
| GitHub | 读取仓库、Issue、PR | 创建 Issue、评论 PR |

每个 adapter 声明认证方式、风险、资源范围、capability、输入 schema、幂等性和 `OutcomeUnknown` 处理，并提供 fixture server 和副作用计数器。OAuth 或测试账户缺失时对应真实集成是 BLOCKED，不以静态页面替代。

连接器通过应用自有 MCP 工具提供给 Pi，所有动作经过同一 policy 服务，不新增绕过授权的执行通道。

### 5.7 定时任务

调度器持久化 cron、IANA 时区、Agent/Profile、工作区、prompt、权限引用、输出位置、revision、上次/下次计划时间、连续失败数和当前 run/session。

调度器必须处理漏跑策略、禁止同任务重入、全局并发上限 2、DST、系统时钟跳变、重启恢复、暂停、删除、立即运行、等待审批和连续失败自动暂停。触发时创建普通 RunService 会话，不实现第二套 agent runtime。无人值守任务遇到未预授权动作时进入 `waiting_approval`，不得自动越权。

### 5.8 资源库、记忆和观测

资源库索引已授权产物，文件系统是内容权威；SQLite 保存路径、哈希、大小、来源 run 和引用关系。支持预览、导入、导出、加入会话和磁盘变化检测。

记忆作为资源库中的独立分区，保留 user/workspace scope、候选确认、来源、过期、删除、搜索和导出。记忆不得和普通产物混成同一种记录；删除只影响后续注入。

观测显示真实 provider usage、工具执行、审批、失败、run 链路和诊断。缺失 usage 或价格时显示 `unavailable`，不显示伪造的零值或费用。

### 5.9 设置

设置包含通用、模型、Pi 运行时、权限、观测、安全、语言、主题、Pi 安装升级和应用更新。V1 只管理宿主 Pi，不显示 Codex CLI 或 Claude Code 为可选运行时。

## 6. 国际化

V1 支持 `zh-CN` 和 `en-US`：

- UI 文案使用稳定消息 key；
- Go 返回稳定错误码和参数，前端负责翻译；
- 日期、时间、数字、文件大小和费用使用 locale formatter；
- 用户内容、模型内容、文件和工具原始输出保持原语言；
- 切换语言立即更新静态和动态客户端文案；
- 设置持久化，首次启动读取系统语言，不支持时回退 `zh-CN`；
- 中英文目录 key 集合必须一致，缺 key、废弃 key 和产品文案硬编码使静态检查失败。

## 7. 主题与布局

交付 Light 和 Dark 两套主题。“跟随系统”是选择方式，不是第三套主题；首次启动跟随系统，手动选择后持久化。

所有组件使用语义 token：background、surface、foreground、muted、border、accent、success、warn、danger、focus、shadow、overlay、spacing、radius、type 和 motion。页面组件禁止直接写主题颜色。

两主题覆盖 default、hover、focus、active、disabled、loading、empty、error、success 和审批风险状态。应用在 React 渲染前应用主题，避免闪烁。远端网页不注入主题；浏览器工具栏、标签、遮挡层和内部产物预览跟随主题。常规文本对比度不低于 WCAG AA 4.5:1，大文本不低于 3:1。

产品仍是 Wails 桌面应用，不新增移动端发行。布局验收覆盖 880×600、1024×720、1366×768、1440×900、1920×1080，以及 Windows 100%/150%/200%、macOS Retina、Linux X11/Wayland。主题切换不得重建浏览器 tab、丢失会话或改变控制权。

## 8. Pi 自动发现、兼容、安装与升级

### 8.1 发现和兼容策略

发现顺序为用户指定、已保存路径、应用托管目录、PATH、常见安装目录。界面显示所有候选的实际路径、版本、发行形式、来源和哈希，按确定优先级选择，不静默切换。

兼容判定采用“版本范围 + 能力协商 + 契约探测”。初始最低支持版本为 1.5.0，默认候选范围为 `>=1.5.0 <2.0.0`；该范围只决定是否进入探测，不直接代表兼容。2.x 及更高主版本在新的 Anvil 兼容清单和契约套件发布前保持 `incompatible`：

- 先检查支持范围；
- 再在隔离 agentDir/workspace/provider 下探测 RPC 握手、完成语义、MCP、extension hook、停止和清理；
- 预先认证版本标记 `ready_verified`；
- 同系列新版本通过探测后标记 `ready_compatible`；
- 探测失败标记 `incompatible` 并展示失败能力；
- 未登记版本不能仅凭版本号直接运行真实会话。

状态为 `discovering / ready_verified / ready_compatible / upgrade_available / incompatible / missing / installing / rollback_available / failed`。

### 8.2 安装升级

缺失时提供一键安装，不兼容或过旧时提供一键升级。下载使用官方 HTTPS allowlist 和受信清单，校验重定向、哈希、签名、归档边界和实际 RPC。安装到 staging，验证成功后原子切换 active，失败或取消不改变当前版本，至少保留一个可回滚版本。

外部 Pi 不被覆盖；升级默认安装为应用托管版本。客户端基础包继续不捆绑 Pi、Node、npm、模型权重或独立 Chromium。

## 9. Anvil 应用自动更新

V1 自动检查并后台下载稳定版更新，但不主动重启。下载完成后显示“下次启动安装”；用户也可选择“退出并更新”。存在活跃 run、审批、Pi 安装、浏览器人工接管、未保存编辑或清理失败时，不强制退出。

更新流程为：

`check → download → verify → ready → normal exit → next-launch apply → health check → commit/rollback`。

清单包含 schema、channel、版本、target、最低升级版本、URL、大小、SHA-256、签名、发布时间、数据库迁移版本、Pi 兼容范围和 release notes。清单与包分别验签，信任根编译进应用；拒绝错误来源、重定向、目标、架构、降级、未知 schema 和校验失败。V1 使用完整包，不实现差分补丁。

平台应用方式：

- Windows：签名 updater helper 在主程序退出后交换版本；
- macOS：验证签名、公证、Team ID 和 bundle ID 后替换 `.app`；
- Linux AppImage：校验后原子切换 active 文件；
- Linux `.deb`：自动下载校验，下一次启动进入系统包管理器授权；无权限时保留包并显示 BLOCKED。

新版本启动、数据库迁移或健康检查失败时恢复旧程序和数据备份。应用更新不修改外部或托管 Pi；Pi 只由独立生命周期流程改变。

状态为 `idle / checking / update_available / downloading / verifying / ready / applying / health_checking / completed / rollback / failed / blocked`。

## 10. 运行架构和数据权威

```text
React pages
   → Go application API
      ├─ versioned JSON + CAS
      ├─ SQLite indexes/state
      ├─ OS credential store
      ├─ RunService → Pi RPC worker
      ├─ ConnectorService → app-owned MCP tools
      ├─ Scheduler → normal RunService sessions
      ├─ BrowserService → native WebView host
      ├─ PiLifecycleService
      └─ UpdateService → signed updater helper
```

Pi transcript 是消息与分支历史权威；SQLite 是 session/run/审批/记忆/产物/调度索引权威；JSON 是配置权威；文件系统是 Skill、扩展和产物内容权威；OS 凭证库是秘密权威。UI 不保存第二份业务真相。

## 11. 错误与恢复

- 后端错误包含稳定 code、message parameters、retryable、operation 和 cause summary；
- 前端按 code 翻译，不匹配中文文本；
- 外部写入超时或断线后返回 `OutcomeUnknown`，不得自动重放；
- 连接器、调度、Pi 安装和应用更新都必须显示下一步修复动作；
- 乐观 UI 只能表示“请求已提交”，不能在后端确认前表示“已完成”；
- 所有删除、替换、迁移和激活操作具备事务、备份或原子交换边界。

## 12. 门禁与防假实现

保留 G0–G5 编号和历史证据坐标：

| Gate | 新通过条件 |
|---|---|
| G0 | 工具链、隔离、Pi 自动发现、版本识别、兼容探测、RPC/扩展/MCP 契约 |
| G1 | 六目标原生浏览器、DOM、截图、焦点、缩放、接管和弹层协调 |
| G2 | Pi 安装升级、会话、模型、Skills、MCP、记忆、连接器、调度、权限和持久化 |
| G3 | Anvil 新 UI、国际化、主题、资源库、观测和真实端到端工作流 |
| G4 | 六目标干净环境安装、首次启动、Pi 安装、应用更新、升级恢复和数据保留 |
| G5 | 正式签名、公证、来源验证和发布清单 |

### 12.1 通用防伪

- 拒绝空 suite、全 SKIP、旧 revision、dirty、重复证据、缺目标和伪造 passed 文件；
- UI 数据必须来自真实 Go API/数据库；
- 保存必须核对磁盘或数据库，并在重启后复查；
- 写操作由 fixture 计数器、文件、进程或服务端日志验证，拒绝时 0、允许时 1；
- 产物核对路径、大小、哈希、来源和磁盘变化；
- 定时任务用可控时钟验证，不等待真实分钟；
- 原生和安装能力必须由构建后的 Wails/安装包验证，静态原型和浏览器 React 测试不能替代；
- 每条证据记录 Task、case、target/display、revision、dirty、命令、退出码、版本、路径、hash、原始日志/截图/录屏、外部 oracle、状态、限制和复核人。

### 12.2 Pi 原子用例

`PI_DISC01–02` 覆盖多来源发现和错误 PATH；`PI_COMP01–04` 覆盖最低、认证、最新兼容与协议不兼容；`PI_INS01–03` 覆盖安装和失败不激活；`PI_UPG01–03` 覆盖空闲切换、回滚和不覆盖外部 Pi；`PI_PKG01–02` 覆盖包内容和干净机器首次安装。

### 12.3 国际化与主题用例

`I18N01–04` 覆盖 key 一致、即时切换、动态状态和中英文布局；`THEME01–05` 覆盖 token、持久化、对比度、状态不丢失和构建后 Wails 截图。页面最低矩阵为两语言 × 两主题。

### 12.4 应用更新用例

`UPD01–14` 覆盖渠道/目标选择、签名/hash、降级和来源拒绝、断点续传、不主动重启、下次启动真实版本变化、健康失败回滚、数据保留、迁移回滚、断电原子性、Pi 不变、六目标真实包升级、包内容扫描，以及中英文 × 浅深主题状态。

更新验收必须启动旧版二进制，通过更新流程启动新版，并从进程/API 读取真实版本。修改 UI 文案、设置值或只写 `UpdateReady` 文件不构成通过。

8. 正式发行只有在 G5 完成后才能对外宣称完成。
