# Anvil 重启技术方案

日期 2026-11-09 · 设计提案 · `RESTART-DESIGN`

## 重启方式

建议在独立目录初始化一个新 Git 仓库，以原型为产品依据，从空项目实现。旧仓库提供原型、Pi 协议样例和已知故障的参考。新仓库只纳入当前里程碑需要的内容，并使用独立应用数据目录、Pi agentDir、会话目录和临时工作目录。已有会话和凭证的迁移是独立决策。

建议沿用现有约定的技术栈。Go 1.27.3 管理宿主进程、会话与 Wails 绑定，Wails v3.0.0 承载桌面窗口，React、TypeScript 和 Vite 实现交互。使用原型的 CSS、图标和资源作为样式基准，Tailwind 和 shadcn 仅在能保持原型效果时使用。宿主 Pi 负责模型请求、对话上下文和 Agent 循环。首轮指定一个已安装且通过兼容检查的 Pi 和一个真实模型，先在本机 Windows x64 跑通。SQLite 等到项目分组、搜索等功能确实需要应用侧索引时引入。

上述仓库边界、首轮平台和单模型配置是本提案的建议。第一轮 Windows 验收只覆盖本机实际验证的范围，后续平台与发行另行验收。开发启动时显式传入 Pi 路径与模型配置，使用隔离的测试凭证，凭证不写入代码、日志、截图或应用配置。缺少兼容 Pi 或测试凭证时，真实验收记为 `BLOCKED`。

## 原型如何进入开发

以 [设计交接](../../ui/Agent-客户端产品原型/DESIGN-HANDOFF.md)、[页面清单](../../ui/Agent-客户端产品原型/DESIGN-MANIFEST.json)、[对话页](../../ui/Agent-客户端产品原型/chat.html) 和其中引用的 CSS、脚本为基准。在新仓库固定一份带来源提交的原型快照。每次只认领清单中本轮要做的区域与交互状态，对照其布局、间距、文字、图标、响应行为、焦点和键盘操作。后续功能按原型预留位置，首轮统一收起相应交互与演示数据，包含右栏、项目控件和其他页面入口。首轮以原型右栏折叠状态比较对话布局，空会话沿用同一布局，消息区保持空白，输入框清空示例文本。第一版直接进入对话，原型 `index.html` 的工作台作为后续独立入口交付。

开发时用固定消息比较原型与桌面截图，覆盖 `1366×768`、`1440×900`、`1024×768` 和 `390×844`，最后一项可用浏览器视口。截图用于验证界面。发送、追问、取消和恢复使用真实 Pi 和模型，单独保存证据。

## 第一轮只交付文本对话

| 步骤 | 交付范围 | 验收 |
| --- | --- | --- |
| `CHAT-01` 首条消息 | 新建空会话，发送文本，显示用户消息和 Agent 的流式回复 | 打开桌面程序发送真实请求，屏幕在完成前出现增量，最终文本完整。Pi 缺失、认证或请求失败时显示可执行的下一步 |
| `CHAT-02` 追问与停止 | 同一会话多轮追问，停止当前回复，停止后继续发送 | 第一轮给一个随机代号，第二轮仅追问代号，回复匹配。发送较长请求，观察到首段后停止，收到 Pi 终态才显示已停止。随后同一会话可继续对话 |
| `CHAT-03` 本地历史 | 左栏普通会话列表、打开旧会话、重启恢复 | 建立两条对话，重启桌面程序后分别打开，历史和上下文互不串线。恢复曾中断的会话时，显示已持久化的内容，并将未完成的轮次显示为中断 |

初期只有一个默认 Agent 和一个真实模型，一次只允许一个生成中的回复。文本、基础 Markdown 和代码块使用对话原型的消息样式，按纯文本或安全 Markdown 渲染。发送按钮与 `Ctrl+Enter` / `Cmd+Enter` 沿用原型行为，普通回车换行，输入法组合输入期间暂停发送快捷键。文件、目录、命令、工具调用、审批、模型切换、附件、项目、分享和右栏均归入后续里程碑。

## 第一轮技术边界

```text
React 对话页
  → Wails 绑定
  → Go 会话服务
  → Pi RPC 子进程
  → 已配置的真实模型
```

- **运行时**。Go 负责启动、输入输出、超时和进程退出。按现有 Pi 最低支持版本、兼容范围与隔离要求准入。真实聊天验收前，对选定的 Pi 二进制单独跑一遍基线的 RPC、终态、MCP、扩展、停止和清理探测，可以用旧仓库探测器在新隔离目录产出本轮证据。探测进程与聊天进程分开。聊天进程显式关掉内建工具、扩展、Skills 和 MCP，在隔离环境验证实际有效的禁用方式，验证失败时拒绝进入会话。具体 Pi 二进制、真实模型及测试凭证由执行时提供。产品 UI 中的 MCP 和扩展按后续里程碑交付。
- **状态**。前端先订阅事件再发送。Go 接受消息时生成轮次 ID，每个事件携带会话 ID、轮次 ID 和递增序号，迟到事件只影响原轮次。界面允许空闲、生成中、停止中、完成、已停止、失败与中断状态。`abort` 响应只表示请求收到，成功完成和停止以通过探测的 Pi 终态协议为准。现仓库的契约样例使用 `agent_settled` 和布尔 `aborted` 字段。运行时或连接异常时保留已显示的部分文本并明确标记失败，停止超时后由 Go 清理进程树。应用退出后用 Pi 持久化内容恢复，未落盘的流式片段只存在于当次窗口。
- **会话**。Pi transcript 保存正文及模型上下文。`CHAT-03` 增加一个原子写入的本地会话索引，记录会话 ID、Pi 会话引用、标题、更新时间与进行中轮次标记。向 Pi 提交前先落盘该标记，收到并确认终态后清除。重启时残留标记作为中断提示，并以 transcript 展示已持久化正文。打开历史通过 Pi 的会话恢复接口继续同一个 transcript，按验证过的协议读取历史。写入或恢复失败向界面返回错误，用户可以重新打开或新建会话。`CHAT-03` 实现前用真实 Pi 校验从持久化会话恢复。
- **最小测试面**。每步先加当前功能的失败用例，再做最小实现。单元测试覆盖事件与终态、停止竞态和会话隔离等可复现分支，真实桌面测试覆盖完整用户路径。每步记录实际命令、退出码、目标平台、Pi 版本、截图与脱敏日志路径及哈希、已知限制，单独提交。截图和测试替身各自用于界面和分支验证，真实运行结论来自桌面程序连接 Pi 和模型的实际结果。

## 聊天跑通后的顺序

| 顺序 | 按原型交付的部分 | 一条可以验收的用户路径 |
| --- | --- | --- |
| 2 | `chat.html` 项目与侧栏历史 | 选择本地目录，归入项目，重启后仍能找到并恢复会话 |
| 3 | `settings.html` 最小运行时与模型设置，`agents.html` 最小 Agent 管理 | 在设置中选择有效模型，在 Agent 页选一个 Agent，下一轮对话使用该配置 |
| 4 | `chat.html` 文件附件、工具事件、澄清与审批 | 逐次交付附件、单个受限工具、审批和澄清。首个工具验收覆盖允许、拒绝、目录边界和停止。澄清单独验收 |
| 5 | `chat.html` 执行、输出物、引用、浏览器右栏 | 每个标签单独验收。先把真实执行事件接入，再展示真实产物并跳回来源轮次，最后接入真实引用和浏览器 |
| 6 | `skills.html`、`mcp.html`、`connectors.html`、`schedules.html`、`library.html`、`index.html` | 每页按真实工作流验收。工作台从已交付模块取最近会话、产物和运行状态 |

上表用于排先后。每次只实施当期那一个可验收的用户路径，失败或缺依赖就停在当期记录证据。等当前路径能现场演示并留下证据，再细化下一项。Pi 安装升级、应用更新、跨平台打包和发布分别做独立交付。第一轮的完成判据是桌面文本聊天闭环，正式发行仍需要单独的发行验收。
