# Anvil 原型重建与分阶段验收

日期 2026-11-09 · `REBUILD-DESIGN`

## 范围与技术基线

按用户确定的顺序重建。阶段 0 复刻九页、主题与中英文。阶段 1 发现并注册多种 Agent，同步模型、Skill、本地工具和 MCP，支持自定义模型。阶段 2 实现原型全部会话功能。每个子任务单独验收，阶段门禁通过后才能开下一阶段。本方案取代聊天优先提案。原型、规格、许可和旧提交可供查证，新分支产品实现从零开始。

沿用 Go 1.27.3、Wails v3.0.0、React、TypeScript、Vite、Tailwind、shadcn 和 SQLite modernc。原型 CSS 决定视觉效果。桌面绑定走 Wails，Go 管理本地运行时，SQLite 管理应用索引。平台仅 Windows、macOS、Linux。先在当前 Windows x64 / Windows 10 22H2 验收，Windows 11、macOS 和 Linux 的支持状态按各自真机证据记录。Windows 产品最低系统为 Windows 10，首轮声明需注明已测最低 build。桌面测试使用隔离的 AppData、凭证与工作区。

## 阶段 0 · 原型界面

基准为 [原型清单](../../ui/Agent-客户端产品原型/DESIGN-MANIFEST.json)、[设计交接](../../ui/Agent-客户端产品原型/DESIGN-HANDOFF.md) 和随附 HTML/CSS/JS。按源文件建立独立页面，保留布局、资源、层级、导航、弹窗、菜单、输入、侧栏、键盘操作与断点。移除设计工具外壳。原型场景保留为隔离的可重放 UI 数据，用来对照静态状态。业务操作只允许在独立的原型验收场景模拟，正常产品界面的未接入操作明确呈现不可用。

| 页面 | 对照区域和必测行为 |
| --- | --- |
| `index.html` 工作台 | 全局壳、导航、统计区、任务、项目入口、新建对话 |
| `chat.html` 对话 | 历史与项目、消息和输入、各异常状态、右侧四栏、窄屏抽屉、全部弹窗 |
| `agents.html` Agent | 列表、详情、筛选、配置表单及对话入口 |
| `skills.html` Skill | 列表和详情、工作流、创建及演练状态 |
| `mcp.html` MCP | 服务列表、详情、工具展示和配置状态 |
| `connectors.html` 连接器 | 列表、授权和连接状态、详情 |
| `schedules.html` 定时任务 | 列表、详情、创建与运行状态 |
| `library.html` 资源库 | 列表、筛选、详情、空态 |
| `settings.html` 设置 | 导航分区、全部面板、语言和外观 |

默认简体中文、主题跟随系统。设置提供浅色、深色、跟随系统及中文、英文，持久化后立即应用到所有页面。跟随系统模式订阅 OS 主题变化，手动模式忽略系统变化。原型只有浅色基准时，深色扩展语义 token，保持几何、字号、图标和层级，单独固定截图基线。翻译覆盖静态文案、状态、动态系统消息、校验、提示、可访问名称。会话正文、路径和用户命名保留原文。

**G0** 每页逐项对照 DOM/交互和截图。覆盖 `360×800`、`390×844`、`430×932`、`600×960`、`820×1180`、`1024×768`、`1366×768`、`1440×900`、`1920×1080`。同机器、字体和固定数据对照浅色中文截图，深色/英文检查溢出、缺词和可读性。以隔离样例入口复现原型的填充状态，常规入口验证空态与不可用操作。每页产出图和差异审阅结果。只允许逐项登记的设计工具标记、字体抗锯齿等差异，布局、内容和交互差异必须修正或取得用户明确接受。Windows Wails 实机验证九页导航、设置重启恢复、系统主题实时变化、焦点和键盘。九页清单与实机证据齐全才能过门禁。

## 阶段 1 · 多 Agent 自动发现和注册

此处的运行时是本机 CLI，模型是其可选推理配置，产品里的 Agent Profile 则引用一条运行时注册和模型。建议第一批 Pi、Codex、Claude Code、OpenCode，逐个适配、逐个取证。Paseo 的 [运行时设计](https://github.com/getpaseo/paseo/blob/180f07587a967a22d53c5ba198c88ee61a731ba5/docs/providers.md) 和 [注册表源码](https://github.com/getpaseo/paseo/blob/180f07587a967a22d53c5ba198c88ee61a731ba5/packages/server/src/server/agent/provider-registry.ts) 用于参考原生适配器与通用协议的边界。Anvil 仍由 Go 管理宿主 CLI，Pi 沿用现有版本约束。ACP 可增加后续覆盖面，单独验收后列为支持。

1. **发现**。启动与手动刷新扫描显式用户路径、PATH、平台已知安装路径，归一化路径并去重。Windows 处理路径空格、安装器 shim 和 PowerShell/npm 的命令解析。路径和版本验证均有超时，禁止扫描任意目录后执行文件。扫描不安装软件、不登录、不启动 MCP。状态区分未安装、已检测、版本不兼容、未认证、可用、探测失败。
2. **注册**。按运行时类型、规范化安装路径与配置实例标识建稳定 ID，刷新更新现有行，单个适配器失败不污染其他结果。应用配置隔离，外部配置只读，授权仍由运行时或应用的凭证接口管理。
3. **同步**。适配器返回能力、资源列表、来源、更新时间、认证/错误。模型取协议提供的可见模型或有来源的清单，并区分已检测与当前账号已验证。Skill 读取安全范围内的元数据，本地工具区分内建工具、已配置命令与实际执行权限，MCP 只读导入声明并脱敏。MCP 连接和工具枚举由明确操作触发，经信任检查后才启动本地命令或访问远程地址。按运行时、配置实例、资源类型和来源去重。刷新成功才替换该来源快照，失败保留旧结果并标记过期，配置删除在下一次成功刷新后反映。
4. **自定义模型**。保存模型 ID、显示名、目标运行时、协议和端点，凭证仅存系统凭证库。保存前校验 ID 和端点，验证按钮走该适配器实际调用。只有运行时能接收并使用该模型时才可设为默认。配置透传缺失的运行时明确显示该能力不可用。测试重启持久化和运行时实际选中该模型。

### 运行时扩展契约

- **统一注册入口**。每种运行时实现一个独立 Go 适配器包，由应用启动时集中注册。注册信息包含稳定且可扩展的运行时 ID、显示元数据和能力声明。拒绝重复 ID。共享发现、目录同步、会话、Wails 绑定和 UI 通过注册表与能力查询工作。新增运行时的功能代码应只涉及适配器包和注册入口，可另增该运行时的验收条目及资源。禁止在共享代码里维护 Pi/Codex 等名单、按运行时名称写分支、使用封闭枚举或为每个运行时增加数据库列。
- **协议细节留在适配器**。适配器负责各自的命令、安装路径候选、版本解析、认证、资源格式、协议事件与错误映射。共享层负责扫描调度、超时、去重、持久化和会话生命周期。显式指定可执行文件路径只能用于已注册的适配器。接入新协议时增加适配器，不从未知命令猜测协议。
- **能力驱动界面和调用**。基础接口覆盖发现与探测。模型目录、自定义模型、Skill、本地工具、MCP 和会话能力各自声明。区分不支持、未验证和已验证可用，空列表只表示一次成功查询无结果。UI 从注册信息和探测结果生成列表及操作状态，未知 ID 也能显示。后端在同步、创建会话和执行操作前再次检查能力，返回可定位的错误。
- **会话绑定注册实例**。新建时记录运行时注册实例 ID 与原生会话 ID，发送、停止和恢复走同一适配器。运行时失效时保留历史并显示可诊断状态。恢复时不得自动把原生会话交给另一种运行时。模型、配置和资源 ID 在所属运行时实例内解析。
- **扩展性验收**。G1 在自动化测试中注册一个此前未知 ID 的测试适配器，走发现、注册、资源同步和 UI 列表通路。G2 复用该契约验证创建、流式事件、停止、恢复的分发。仅通过注入适配器完成接入，并覆盖重复注册、缺失可选能力和适配器失效。真实桌面及真实 CLI 用例独立取证。

**G1** 逐运行时在 Windows 真实二进制上证明路径、版本、兼容握手、状态、重扫去重、移除后变更和可执行能力。分别验证模型/自定义模型/Skill/本地工具/MCP 的来源、刷新失败、重复冲突、无敏感字段泄露和同步结果可被 UI 读取。Pi 与 Codex 必须可运行且完成真实认证验证。Claude Code 和 OpenCode 必须有真实安装、发现和注册证据，其他能力按适配器能力矩阵验证。至少一个可配置的运行时真实验证自定义模型。缺安装、认证或必要服务的必测项记为 BLOCKED。声明不可用的能力必须有真实探测或协议依据，不能用空列表冒充成功。所有必测矩阵项及运行时扩展契约测试通过后才能进会话。

## 阶段 2 · 原型完整会话

| 子门禁 | 用户可验收的闭环 |
| --- | --- |
| C1 | 从工作台、Agent 或历史入口建会话，选运行时、模型、思考级别和权限，真实发送、流式回复、追问、停止、重试，覆盖认证失败、上下文超限、异常退出、恢复和并行会话隔离 |
| C2 | 普通/项目会话，选本地目录、分组、分页、搜索、置顶、重命名、归档、删除，重启后恢复；分支和压缩由支持它的运行时实现 |
| C3 | 添加文件、目录、Skill、@ 引用及清理，展示真实工具调用，澄清与执行审批分开，覆盖允许、拒绝、取消、迟到事件及越权路径 |
| C4 | 右栏浏览器、输出物、引用、执行与用量，宽窗折叠与窄窗抽屉，产物能跳回来源轮次，显示真实数据 |
| C5 | 本地 HTML/Markdown/JSON 导出；原型外部分享按明示上传范围和用户确认独立验收。缺分享服务时本项为 BLOCKED |

Go 按会话绑定运行时与原生会话 ID，保留原生 transcript 为正文来源。SQLite 保存应用侧 ID、项目、索引及轮次状态，恢复后按运行时实际能力继续对话。事件包含会话 ID、轮次 ID 和序号，终态只由适配器从真实协议映射，取消请求收到与取消完成分开。运行前固定模型、工作目录和权限快照，前端根据能力显示可用选项。模型回退、运行授权、审批、文件外发和重试都须有真实事件及可追溯结果。

**G2** 会话扩展契约测试必须通过。C1 在至少两个已认证运行时跑真实会话，C2–C5 按原型功能矩阵逐项验收。运行时能力差异按矩阵记录，并用至少一个真实支持该功能的运行时证明每项原型能力。执行 C1 前登记运行时能力矩阵，C2–C5 各项开工前指定至少一个能证明能力的运行时或本地实现。必测功能缺运行时能力或真实服务时记为 BLOCKED，门禁保持关闭。工作台、Skill、连接器、MCP、计划任务与资源库在这三个阶段只接入其所需界面及会话/同步链路，独立业务闭环另开任务。

## 门禁通用规则

每个 Task 有失败用例、最小实现、focused 命令、原始证据、独立提交和负责人自检。验收矩阵状态为 PASS、FAIL、BLOCKED 或 NOT_RUN。报告记录实际命令、退出码、测试系统与 build、运行时版本、Git SHA、截图及脱敏日志路径/hash。阶段门禁将所需用例及真实/原型场景标记纳入检查，证据缺失、仅 mock、串用旧证据或目标不一致都不能通过。退出码 0 为通过，1 为已有证据表明失败，2 为配置缺失、用例缺失、BLOCKED 或 NOT_RUN。具体执行命令见配套计划。
