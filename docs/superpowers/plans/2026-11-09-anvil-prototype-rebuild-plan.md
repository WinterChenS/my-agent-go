# Anvil 原型重建实施计划

> 逐任务实施。每项先写失败用例并确认失败原因，再做最小实现，运行 focused 验证，保存原始证据，最后用 Task ID 独立提交。阶段只按 G0 → G1 → G2 推进。

**目标** · 九页原型复刻与主题/i18n，多运行时发现和同步，最后实现原型完整会话。
**架构** · Wails 桌面窗口承载 React 页面，Go 提供类型化 Wails 绑定、运行时适配和持久化，SQLite 保存应用索引。
**技术栈** · Go 1.27.3、Wails v3.0.0、React、TS、Vite、Tailwind/shadcn、modernc SQLite。
**规格** · [原型重建设计](../specs/2026-11-09-anvil-prototype-rebuild-design.md)
**范围** · 仅本设计的阶段 0、1、2。当前 Windows x64 / Windows 10 22H2（build 19045）先跑通。

## 执行方式与证据

实施派发、客户端实测及本机 Pi 的使用要求见[实施与真实验收规范](../specs/2026-11-09-anvil-rebuild-execution-standard.md)。

计划中的命令由 `R0-00` 新建。例 `powershell -ExecutionPolicy Bypass -File scripts/devtools.ps1 verify --case=R0-01 --target=win-x64`，结束时执行 `powershell -ExecutionPolicy Bypass -File scripts/devtools.ps1 gate --id=G0 --target=win-x64 --evidence=<absolute-path>`。G1/G2 同理。命令透传进程退出码，0 通过，1 断言失败，2 输入或证据不完整。验收矩阵 `tests/acceptance/rebuild.json` 串行维护。证据保存在隔离目录 `<evidence>/<sha>/<target>/<case>/`，含命令、退出码、真实/界面数据来源、OS build、应用版本、运行时版本、日志或截图的相对路径与 SHA-256。不同提交的结果先确认代码与用例适用范围，再在门禁目标提交上重跑必要用例；门禁拒绝错误 SHA 或错误平台。

每项的 **失败用例** 是先写的断言，**实现** 给出入口和边界，**验收** 是必须运行的结果。阶段变动由用户决定。先按每个 Task 查工作树，禁止同时开始多个后续阶段。

## 实施记录（阶段 2，2026-11-13）

右栏与导出落地时，计划里三处设想被实测改写，记在这里：

| 初版设想 | 实测 | 现在的做法 |
| --- | --- | --- |
| 右栏四栏都由"页面状态"喂数据 | 页面没有真相：产物、引用、执行都在账本里 | `rail` 从 `events`/`messages`/`runs` 现算；产物再看磁盘（存在与否、字节数），项目外路径只计数不展示 |
| 引用编号由前端按渲染顺序生成 | 前端顺序依赖滚动与分页，和后端不一致就会出现"点 [2] 跳到第 3 条" | 编号由后端按首次出现分配，前端只渲染同一个数字；没有对应来源的 `[n]` 保持纯文本 |
| 浏览器栏要接外部浏览器通道 | 本机没有可自动化的外部浏览通道；伪造一个"已打开"没有意义 | 只把**项目内产出的本地 HTML**放进 `sandbox=""` 的 iframe（禁脚本、禁同源、禁跳转），没有页面时如实说明；外部分享/外链一律记为不可用 |
| 导出失败只当普通错误 | 目标被目录占用时旧实现会留下 `.part` 半文件 | 写入一律先落临时文件、任何失败都清理；覆盖需要显式确认；工具参数默认不导出 |

三个被真实链路抓到的缺陷（都不是用例本身的问题）：

- **聊天页只读一次目录快照**。冷数据目录下首次扫描（探测所有已装运行时）晚于这次读取，页面就永久停在"正在连接"、输入框一直禁用，唯一出路是手动点同步。现在有界等待首次扫描（90 秒）。
- **右栏跳转调用了 `scrollIntoView` 而未防缺席**。部分 webview 没有该方法，调用即抛错，高亮分支根本走不到。
- **R2-02…R2-05 新增的 7 个会话命令只登记在 ACL，没进 `generate_handler!`**。契约测试核对了 `APP_COMMANDS`、权限文件与 capability 三张表，却没核对真正派发命令的宏；于是真窗口一进聊天页就 `Command session_projects not found`，页面进入错误态、输入框永久禁用，项目分组/分支/压缩/审批/引用/右栏/导出在桌面端一个都调不到。自动化用例全走 `session_report` 与单测，恰恰绕过了这条链路。现在由 `host_contract` 断言宏体与 `APP_COMMANDS` 完全一致，并由两个原生用例真实调用兜底。

`R2-05` 的外部分享没有服务可用：未实现、未注册为必测，记录为不可用，不用本地模拟冒充通过。

## 实施记录（体验反馈，2026-11-14）

把免安装包交给用户实际试用，第一次真机反馈就抓到两个此前所有用例都照不到的问题——它们都在"账本到像素"这一段：

| 反馈 | 根因 | 现在的做法 |
| --- | --- | --- |
| 输入框的模型下拉是白色的，不跟主题 | `.chat-ctl select` 只写了 `background: transparent`，弹层由 WebView2 按**系统**调色板绘制，深色主题下必然白底；`option` 也没有任何主题声明 | `select`/`option` 显式使用设计 token 的背景与文字色，并补 `color-scheme: dark/light`，让原生弹层跟随页面主题 |
| 发消息后一直"正在生成"，很久没有回信 | 回合只有宿主侧 300 秒预算，页面没有任何截止时间与失败态；期间只显示一句"正在生成"，没有阶段、没有工具卡、没有失败出口——一个卡死的回合和一个正常工作的回合长得完全一样 | 页面 120 秒封顶，到点主动 `abort` 并渲染可重试的状态卡；回合按真实账本事件渲染原型词汇：阶段清单（会话/上下文/工具/审批/流式/完成）、工具卡、审批卡、用量、流式光标与等待计时 |

顺带修掉一个只在连续对话中暴露的问题：事件轮询从 `seq 0` 开始，第二轮回放第一轮的增量文本，屏幕上会出现上一轮的句子重复出现。现在每个会话持有一个跨轮次的 seq 游标。

这两项用 197 条页面测试、前端构建和包内二进制真启动验证；原生用例断言的是输入框可用、真实回信与右栏四栏，**没有**对阶段清单做像素级截图断言——这一点如实记录，不当作已覆盖。
