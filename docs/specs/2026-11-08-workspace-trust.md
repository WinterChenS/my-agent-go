# 工作区信任：三个改动（2026-11-08）

用户指出三件事，都属于"信任"这条链路上的体验问题：

1. **聊天页面「工作区尚未信任」时应能直接点授权**，而不是让用户自己去找左栏那把锁。
2. **需要一个"已授权工作区"列表**，能看到、能撤销——否则信任是一次性动作，事后无从核对。
3. **选择项目目录不应该需要授权**：选目录只是"我要在这里工作"，不是"允许在这里执行命令"。

## 决策

1. **信任的语义只覆盖"执行"**：`workspace.trusted=false` 时禁止 shell/写文件/执行类工具；
   读取、会话创建、选择目录、历史、导出都不受影响。选目录与信任彻底解耦。
2. **聊天页就地面包屑式授权**：就绪阻断卡给一个"信任此工作区"按钮（显示它绑定的是哪个绝对路径），
   点一次即 `SetWorkspaceTrust(id, true)`；成功后自动重算就绪，无需刷新页面。
   风险文案里写清"允许在该目录执行命令与写入文件"，别只说"信任"。
3. **信任列表**（设置 → 工作区）：已信任的逐条列出（名称 / 绝对路径 / 信任时间 / 撤销），
   未信任的也列出并标注——列表的价值在于"能核对差异"，只列已信任会让人以为其它目录不存在。
4. **撤销立即生效并将影响说清**：当前正在该目录跑的 run 不被打断（run 已按受理时的 binding 执行），
   但下一个 run 会重新阻断；撤销时给出这句话，避免用户以为"撤销了还在跑"是 bug。
5. **信任状态是持久事实**（已有存储），不因重启丢失；不提供"全局信任所有工作区"的开关——
   那等于把第 ①.5 条的 `full_access` 和目录边界混成一个东西。

## 验收（agent-desktop 真机）

| 步骤 | 断言 |
|---|---|
| 选一个未信任目录作为工作区 | 不弹任何授权，目录正常进入、历史可见 |
| 聊天页发送 | 就绪卡出现"信任此工作区"按钮，按钮文案含该目录绝对路径 |
| 点该按钮 | 一次点击后即可发送（不再要求去别处），事件/设置里 `trusted=true` |
| 设置 → 工作区 | 已信任与未信任都在列表里，路径与时间可见 |
| 点"撤销" | 列表状态翻转；下一条消息重新被阻断；正在跑的 run 不受影响 |

## 归属

并进第 ①（会话页 + 就绪链路），因为它是"发不出去"的第二个阻塞点；信任列表属于设置页，可与 ① 同批。
