## 已确认

- Go 为客户端 Harness 主体，桌面宿主选择 Wails。
- Windows/macOS/Linux 跨平台安装包是首版交付要求。
- 底座使用本地 Pi，客户端安装包不携带 Pi 运行时；已有安装可选择，缺失时支持一键安装。
- 管理 skills、模型、MCP、tools、记忆等 Harness 能力。
- 工作台右侧有浏览器，Agent 能操作；已研究 GooeyPi。Wails 原生浏览器路线需要三端原型验证。
- 前端当前方案为 React + TypeScript + Vite + Tailwind CSS + shadcn/ui；是已提出的推荐，未单独收到用户明确选型回复。

## 技术验证项，不要求用户替开发者选择底层细节

1. Wails NativeBrowserHost 的三端挂载、UI 线程、焦点、弹层遮挡及生命周期；必要时最小宿主集成 hook 的维护成本。
2. Pi 兼容版本、RPC/扩展协议、自有 MCP、独立发行包一键安装；宿主 Pi 更新后的兼容检测。
3. 现有 Pi auth/OAuth 与独立 agentDir 的实际兼容方式、凭证存储适配。不能同时宣称独立配置与自动读取已有登录都已解决。
4. SQLite 驱动、迁移方式、中文 FTS 检索质量；依据原生构建需求选择驱动，不让用户在实现细节中做无必要选择。
5. 三端凭证库、系统 shell/脚本依赖、进程树清理、平台 SDK 与构建工具；本地能编译 Windows 不代表具备 macOS/Linux 验收环境。
6. 应用更新与托管 Pi 更新分开，版本清单和下载哈希验证；支持源受限、失败重试及回滚。
7. 浏览器数据按工作区/profile 保存，Pi、应用配置、记忆、浏览器 cookies 的备份与导出边界。
