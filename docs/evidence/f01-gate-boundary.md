# F01 门禁边界说明（gate 只校验结构完整性）

本文件明确 `cmd/devtools gate` 的能力边界。这是 v1-gates.md §4 末尾纪律的落地说明：

> 签名/公证/人工审查涉及人或外部凭证；脚本不能自行生成“已签名”“已审查”字段当证据。结构校验通过不是事实审查通过。

## 1. gate 实际能校验什么

`internal/devtools/gate.go` 对每条 `GateEvidence` 做**结构完整性**与**自洽性**校验：

- 必需 case 是否在证据树中存在（缺 case → 判死）；
- `targetId` 是否属于已知六目标（未知 target → 判死）；
- `sourceRevision` 是否与当前仓库 revision 一致（旧 revision → 判死）；
- `versionsLockHash` 是否与 `build/versions.lock.json` 当前哈希一致（过期/篡改 → 判死）；
- `reviewer.name` 与 `reviewer.machine` 是否非空（缺审查人/机器信息 → 判死）；
- `reportHash` 与按证据目录文件重新计算的哈希是否一致（报告被篡改 → 判死）；
- `caseResults` 是否非空且非全 `SKIP`（空 suite / 全 skip → 判死）；
- 子进程真实 `exitCode` 是否为 0（非零 → 判死）。

## 2. 结构通过 ≠ 事实审查通过

以下结论**无法**由 gate 自动得出，必须由独立人工/机器审查确认：

- 证据文件齐全且自洽，不代表用例**真的在目标机器上**跑过；
- `reviewer` 字段存在且非空，不代表审查人**真的**人肉核对过结果；
- `reportHash` 一致只说明文件未被事后改动，不代表原始执行过程真实、未被伪造后再哈希；
- 原生浏览器、发行包等依赖**真实机器/真实签名**的结果，结构校验通过不能替代独立审查与独立复核；
- 证据哈希保证**一致性**，不证明**机器真实存在**或**行为真实发生**。

因此：gate 判 PASS 仅表示“证据结构完整、彼此自洽、与当前基线一致”，不等同于产品能力已被事实验证。涉及签名、公证、人工接管、native 行为判定的用例，必须保留可独立复核的机器元数据、录屏/截图、步骤与审查人，且审查由人/独立流程负责，脚本不得自行填“已审查”。

## 3. 已知限制（F01 范围）

- F01 不实现 integration/native/e2e/package 的 runner，对应 `verify --suite=*` 返回 2，不自动发现空目录判成功；
- F01 不实现 `package` 命令，返回 2；
- G0–G5 当前均无执行证据，故 `gate --id=G*` 一律判死（退出 2），这是预期且诚实的状态。
