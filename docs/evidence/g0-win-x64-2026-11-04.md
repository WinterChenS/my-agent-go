# G0 Windows 单目标证据与门禁结论（2026-11-04）

结论先说：**G0 未通过（exit 2），但性质变了。** 以前是「win-x64 也缺 6 条证据」；
现在 **win-x64 的 14 条目标维度证据 + 10 条 HOST 证据全部 PASS**，缺的是另外五个
目标的真实机器。这是环境缺失（BLOCKED），不是实现失败。

## 4. 门禁按目标汇总（原文）

```text
基线 revision=c77b950 worktreeDirty=false 证据根=docs/evidence/runs/c77b950/win-x64
passed=false exitCode=2 必需证据位=94
通过 24 / 不通过 70
按目标汇总（仅供参考，全矩阵才是门禁结论）:
  (HOST 任一目标)            10/10 ✓本目标自身齐全
  linux-arm64            0/14
  linux-x64              0/14
  mac-arm64              0/14
  mac-x64                0/14
  win-arm64              0/14
  win-x64                14/14 ✓本目标自身齐全
```

为什么 94 条：G0 的 case 里有 14 条 `scope=ALL`（六目标各一份）和 10 条 `HOST`
（任一目标，出现多份则每份都必须通过）。本机只有 win-x64，所以 24 条通过、
70 条缺证据。

## 5. 这轮修掉了两个会「看起来绿」的缺陷

1. **门禁聚合丢平台维度**（`a329d81`）：旧实现 `found[caseID]` 互相覆盖，
   同一 case 的任意单份 PASS 就能满足整个 case；Linux 的 X11/Wayland 也被合并。
   现在按 case × target × display 判定，重复证据 / 串用 gate / dirty 工作区证据
   一律判死，并有 12 条回归用例（含「六目标齐全必须判过」的正向对照）。
2. **集成测试改写历史证据**（`c77b950`）：F02/F04 测试直接写
   `docs/evidence/raw/*.json`，跑一次 verify 就把已提交的历史记录改成当前参数，
   还让工作区变脏、下一轮证据被 `worktreeDirty` 判死。现在默认不落盘
   （`MYAGENT_EVIDENCE_DIR` 显式开启），且 `verify` 检测「运行前干净、运行后变脏」
   直接 exit 2。

## 6. 仍未闭合的部分（BLOCKED）

- `win-arm64`、`mac-x64`、`mac-arm64`、`linux-x64`（X11+Wayland）、`linux-arm64`
  （X11+Wayland）：本机没有这些环境。要闭合必须在这五个目标上分别执行
  `verify --suite=integration --target=<id>`，把证据树合并后再跑 gate。
  历史 CI（`docs/evidence/ci-verify-round3.md`，run 41647730697）只能作为更早源码的
  历史记录，不能当作当前 revision 的证据。
- 推送到 GitHub 触发 CI 需要用户授权（交接文档明确：推送与公开发行按用户后续授权）。
- `SEC07`、配置存储、DB、RUN、MOD 等 G2 用例不在 G0 必需集合内，本轮未生成证据。

## 7. 复现

```powershell
git checkout c77b950
powershell -ExecutionPolicy Bypass -File scripts/devtools.ps1 verify --suite=integration --target=win-x64
powershell -ExecutionPolicy Bypass -File scripts/devtools.ps1 gate --id=G0 --evidence=docs/evidence/runs/c77b950/win-x64
```

第二条必须退出 2；如果它在只有 win-x64 的机器上返回 0，说明聚合逻辑又被改坏了
（回归用例 `TestGateRejectsAllScopeMissingOneTarget` 会先红）。
